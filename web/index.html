信任评级三档：直连已验证 通过对拍验证；声明未验证 网关自声明、暂无对拍证据；未验证 无声明或拒测。详见下节。

信任与合规不看声明，看行为指纹；政策类结论挂证据链接，接受 PR 纠错

渠道来源难以直接"证明"，本评测的立场是行为指纹组合：工具调用是否被剥离、流式是否真实（逐 chunk 计时）、usage 是否被虚报（本地重算比对）、延迟特征是否与官方一致——多个黑盒可测信号共同画像，而非采信网关自我声明。条件具备时再做 K2 式与官方 API 对拍（固定请求集比对 finish_reason F1 与 schema 合法率）。数据留存与主体资质来自条款原文人工标注，附标注日期。

网关渠道来源对拍验证 Prompt 留存用于训练经营主体发票证据

行为体检黑盒拨测出的"它给的是不是真东西"——不看声明，看实测

每项都是固定脚本可复现的黑盒探测：模型回显响应 model 字段是否与请求一致（揪偷换）·工具调用是否被剥离 ·流式真实是否憋完再吐装流式 ·CJK 完整中文输出是否损坏（量化降智 tell）·上下文长文本里的标记是否被悄悄截断。绿=全部探测模型通过，红=有模型未通过，—=暂无可判定数据。

这些信号不构成有罪推定：单次失败可能是网络抖动或模型本身能力所限，看的是持续多次的稳定表现。usage 指纹列给"每 token 字符数"，同一模型跨网关该值异常偏低=疑似虚报 token，需对照官方基线（基线对齐后点亮比对）。

价格USD / 1M tokens（输入 / 输出）· 倍率 = 网关价 ÷ 官方价 · 官方价源自 litellm 开放价格库

自测指南用你自己的 key，三分钟拨测任意一个网关

榜单上没有你在用的网关？或者想亲自验一下它给的是不是真模型？把它加进 data/gateways.json，用你的 key 在本地跑同一套拨测脚本——和榜单完全一致、可复现。

# Node ≥ 20，零依赖。克隆后：
git clone https://github.com/cuihuan/llm-gateway-bench && cd llm-gateway-bench

# 一次性拨测某个网关（OpenAI 兼容端点），看它的真实表现：
YOUR_KEY=sk-... node probe/probe.mjs --samples 3 --gateway <id> --out data/results

# 聚合并本地起看板：
npm run aggregate && npm run serve   # → http://localhost:8080

它测出来的"行为指纹"

工具调用是否被剥离 · 流式真实性（假流式 = TTFT≈总延迟后一次性吐）· usage 重算（每 token 字符数异常偏低 = 疑似虚报）· TTFT/吞吐实测分位数。

为什么可信

探测 prompt、采样数、判定阈值全写在脚本里，带随机串防缓存；原始结果逐次 commit 进 data/results/，任何人可用自己的 key 复现同一结论。不做黑箱加权总分。

把你的网关加进榜单

PR 修改 data/gateways.json（填 baseUrl / authEnv / probeModels），维护者在 Secrets 配 key 后自动进入每 6 小时拨测，数据随时间积累。

方法论摘要 — 拨测：GitHub Actions 每 6h，固定 prompt 流式请求，每模型 3 采样报分位数，并发 ≤4（拨测不是压测）；cron 抖动以真实时间戳为准。政策类标注必须附证据链接与日期。

公正性 — 原始数据逐次 commit 于 data/results/，任何人可用自己的 key 复现；维护者与某网关存在利益关联时在条目中披露。
